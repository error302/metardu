## 2024-05-18 - Missing DOMPurify Wrapping on Dynamically Generated SVG
**Vulnerability:** Dynamically generated SVG content from survey and deed plan components was rendered directly using `dangerouslySetInnerHTML` without proper DOMPurify sanitization. Additionally, the previous DOMPurify whitelist in `sanitizeHtml` was manually maintained and incomplete. Attempting to blanket ban `href` caused regressions on normal `<a>` tags.
**Learning:** Manual tag allowlists for complex elements like SVGs are error-prone and can either cause functionality regressions (by stripping essential tags) or leave XSS vectors open. The built-in DOMPurify profiles provide a much more robust baseline. Also, global attribute bans (like `FORBID_ATTR: ['href']`) break standard HTML features; target specific elements (like `<svg>`) using DOMPurify hooks when enforcing stricter constraints.
**Prevention:** Always wrap dynamically generated SVG output with `sanitizeHtml` when using `dangerouslySetInnerHTML`. Rely on DOMPurify's built-in `USE_PROFILES: { html: true, svg: true }` rather than manual whitelists. Use hooks (`DOMPurify.addHook('uponSanitizeAttribute')`) to conditionally strip risky attributes like `href` or `xlink:href` only from SVG-namespace nodes, preserving valid uses elsewhere.
