## 2024-10-25 - Fix XSS in SVG Plan Renderers
**Vulnerability:** The application generated SVG representations for Deed Plans and Mutation Plans and rendered them using `dangerouslySetInnerHTML`. Because these SVGs were manually constructed using string interpolation and potentially contained user-supplied descriptions and identifiers without proper HTML sanitization before being set, they were vulnerable to Cross-Site Scripting (XSS). An attacker could inject malicious scripts or tags (e.g., `<foreignObject>`, `<script>`) via fields like plan description or surveyor name.
**Learning:** Even if `escapeXml` is used selectively (like in `deedPlanRenderer.ts`), manually building dynamic SVGs and trusting them entirely with `dangerouslySetInnerHTML` is brittle. The codebase already had a carefully configured DOMPurify wrapper (`@/lib/security/sanitize`), designed to permit inert SVG drawing elements while stripping XSS vectors. We learned that applying this sanitizer immediately before injection is a critical defense-in-depth step that was missed in newer component generators.
**Prevention:** Always wrap dynamically generated SVG or HTML strings with `sanitizeHtml` (or equivalent DOMPurify wrapper) immediately when passing them to `dangerouslySetInnerHTML`. Never rely exclusively on upstream data escaping or manual XML sanitization routines.
