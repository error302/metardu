## 2025-02-27 - Safe SVG Sanitization via DOMPurify
**Vulnerability:** DOMPurify using `FORBID_ATTR: ['href', 'xlink:href']` globally breaks standard HTML `<a>` links while attempting to block SVG External Resource vulnerabilities (SSRF / XSS) such as `<image href="malicious.url">`.
**Learning:** We need to parse SVG geometry (which is inherently an HTML/XML injection risk via `dangerouslySetInnerHTML`) while stripping XSS vectors. However, blanket removing `href` breaks standard navigation. The solution is using `USE_PROFILES: { html: true, svg: true }`, `FORBID_TAGS: ['image', 'foreignObject']`, and crucially, a custom DOMPurify hook (`uponSanitizeAttribute`) to selectively target and drop `href`/`xlink:href` *only* when the element namespace or tag is SVG-related.
**Prevention:** Always use the centralized `sanitizeHtml` wrapper from `@/lib/security/sanitize` when rendering dynamically-generated SVGs via React's `dangerouslySetInnerHTML`. Furthermore, omit `sanitizeHtml` on static trusted enums (e.g. constant beacon symbols) to prevent unnecessary hydration overhead or errors.
