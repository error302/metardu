## 2025-02-27 - Dynamically Generated SVGs require DOMPurify explicitly
**Vulnerability:** Application components (`DeedPlanGenerator` and `MutationPlanGenerator`) dynamically generate SVG content containing user inputs and insert them into the DOM via `dangerouslySetInnerHTML`. An XSS payload in user input could have been executed since the SVG wasn't sanitized before insertion.
**Learning:** `dangerouslySetInnerHTML` is extremely vulnerable when taking SVG strings that are dynamically computed from potentially unsafe data. Standard sanitizers may strip all `<svg>` elements if not configured correctly. In this codebase, the strict whitelist in `src/lib/security/sanitize.ts` is carefully maintained to allow inert SVGs (for graphs/maps) while stripping malicious elements (e.g. `<image href="...">`, `<script>`, `onload`).
**Prevention:** Any dynamic SVGs being injected into the DOM via `dangerouslySetInnerHTML` MUST ALWAYS be wrapped with `sanitizeHtml(...)` from `@/lib/security/sanitize`. Ensure `sanitizeHtml` keeps the SVG strict whitelist and does not rely on `USE_PROFILES: { svg: true }`, which breaks XSS protection against things like `href`.
