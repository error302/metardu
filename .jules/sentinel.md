## 2024-11-05 - Missing sanitizeHtml on dangerouslySetInnerHTML in SVG Rendering
**Vulnerability:** Found multiple usages of `dangerouslySetInnerHTML` in generator components (e.g. `DeedPlanGenerator` and `MutationPlanGenerator`) that render dynamically generated SVGs (`output.svg`, `svgOutput`) directly without passing through `sanitizeHtml`. This poses a stored/reflected XSS risk if any attributes in the generated SVG are influenced by user input (like parcel names or point labels).
**Learning:** Even though SVGs are meant for graphics, they are a common vector for XSS in web applications (e.g., embedded `<script>` or `onload` handlers). The project provides `@/lib/security/sanitize` for stripping out unsafe tags and attributes from HTML and SVGs via DOMPurify, but it wasn't being used consistently. Note that static assets or trusted enum definitions (e.g., beacon symbols) shouldn't be sanitized due to React SSR/hydration issues, but dynamic user-influenced SVGs must be.
**Prevention:** Always wrap dynamically generated SVGs with `sanitizeHtml(svgString)` when rendering them with `dangerouslySetInnerHTML`. Double-check any `dangerouslySetInnerHTML` usage during code review to ensure the input is either purely static/trusted or properly sanitized.
