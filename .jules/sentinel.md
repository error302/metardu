## 2024-10-31 - DOM XSS via Unsanitized SVG Rendering in Generators
**Vulnerability:** Found multiple instances where locally generated SVG strings (Deed Plan and Mutation Plan generators) were rendered directly into the DOM using `dangerouslySetInnerHTML` without sanitization. While the SVG strings are generated client-side, they incorporate user-supplied inputs (e.g., project names, parcel numbers). If these inputs are not properly escaped during generation, an attacker could inject malicious scripts (`<script>`) or elements into the SVG, which would execute when rendered.
**Learning:** Even when SVG content is "locally generated" rather than fetched from an external source, it can still be an XSS vector if it includes unsanitized user inputs. Relying solely on XML escaping within the generator function is brittle and error-prone (defense in depth is required).
**Prevention:** Always apply a robust sanitizer (like DOMPurify, wrapped in `@/lib/security/sanitize` as `sanitizeHtml`) at the presentation layer (immediately before `dangerouslySetInnerHTML`) to ensure any injected malicious content is stripped out, regardless of how the SVG was constructed.
