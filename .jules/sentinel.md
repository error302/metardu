## 2024-11-09 - [HIGH] Fix XSS Vulnerability in SVG Rendering via dangerouslySetInnerHTML
**Vulnerability:** The application was vulnerable to Stored and Reflected Cross-Site Scripting (XSS) due to unescaped strings embedded inside SVG content generated dynamically for the Mutation and Deed Plan features. These SVGs were inserted into the DOM directly using `dangerouslySetInnerHTML` and `document.write` for printing, without applying proper sanitization. Simple XML escaping was insufficient as it does not prevent DOMPurify bypasses like executing JavaScript inside tags when the payload is re-parsed.
**Learning:** XML escaping alone (e.g. `escapeXml`) only protects text content nodes. Complex DOM structures such as SVGs when passed dynamically to `dangerouslySetInnerHTML` require deep structural sanitization that ensures no event handlers, external references (like `<foreignObject>` or `<image>`), or scripts are inadvertently rendered by the browser's HTML parser.
**Prevention:** Always use `sanitizeHtml` from `@/lib/security/sanitize` when rendering dynamically-generated SVGs, especially those constructed from user-supplied inputs, regardless of whether internal interpolation handles basic escaping. Ensure DOMPurify configurations specifically lock down allowed tags and strip all `on*` events for SVG scopes.
