## 2026-08-30 - DOMPurify Strict Allowlist Breaking SVG Rendering
**Vulnerability:** The `sanitizeHtml` function used a strict, rigid allowlist for `ALLOWED_TAGS` and `ALLOWED_ATTR` that was blocking all nested drawing elements inside `<svg>`, breaking the application's survey plan viewers and causing them to render empty canvases. Concurrently, new vulnerabilities were found where users' SVGs in `DeedPlanGenerator` and `MutationPlanGenerator` were being rendered un-sanitized via `dangerouslySetInnerHTML` and `document.write()`.
**Learning:** DOMPurify's rigid whitelist approach can be overly restrictive for complex SVGs, leading developers to bypass sanitization entirely (as seen in the un-sanitized generators). Using DOMPurify profiles (`USE_PROFILES: { html: true, svg: true }`) is a better approach than manually whitelisting SVG vocabulary, provided that dangerous tags like `foreignObject` and `image` are explicitly forbidden (`FORBID_TAGS`). Hooking into DOMPurify's attributes pipeline (`DOMPurify.addHook`) allows safe, selective attribute stripping (e.g. `href` and `xlink:href` in SVGs) without globally breaking standard HTML `<a>` links via `FORBID_ATTR: ['href']`.
**Prevention:** Configure DOMPurify utilizing `USE_PROFILES` with `FORBID_TAGS` instead of rigid manual allowlists for dynamic SVG content. Wrap all SVG outputs and user input interpolations with `sanitizeHtml` before passing to `dangerouslySetInnerHTML` or `document.write`. Always use hooks (`DOMPurify.addHook` and `.removeHook`) for context-aware attribute sanitization, rather than global configuration overrides.
