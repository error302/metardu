## 2024-10-02 - Prevent XSS in dynamically generated SVG plans
**Vulnerability:** The `DeedPlanGenerator` and `MutationPlanGenerator` components were dynamically generating SVGs and injecting them into the DOM using `dangerouslySetInnerHTML` without proper client-side sanitization.
**Learning:** Although upstream generation functions (like those in `src/lib/compute/deedPlanRenderer.ts`) attempted to prevent XSS by escaping XML via `escapeXml`, injecting generated markup directly into the DOM still creates a stored/reflected XSS vector. If the upstream escaping logic contains a flaw, or if new unescaped properties are introduced to the generator functions in the future, it would result in an immediate XSS vulnerability.
**Prevention:** Always use defense-in-depth when injecting raw HTML/SVG via `dangerouslySetInnerHTML`. We must apply `sanitizeHtml` from `@/lib/security/sanitize` to the final SVG string immediately before it is passed to `dangerouslySetInnerHTML`. This ensures that even if upstream generating functions produce malicious markup, DOMPurify will strip the offending payloads before execution.
