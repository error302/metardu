## 2024-05-24 - Cross-Site Scripting (XSS) via SVG Generation

**Vulnerability:** Found multiple instances where SVG content was rendered directly using `dangerouslySetInnerHTML` without proper sanitization (e.g., `output.svg` in `DeedPlanGenerator.tsx` and `svgOutput` in `MutationPlanGenerator.tsx`). Malicious users could potentially inject malicious JavaScript inside `<svg>` elements (e.g., using `<a>` tags with `javascript:` payloads or `<script>` tags if `DOMPurify` wasn't properly configured or applied).
**Learning:** `dangerouslySetInnerHTML` is inherently dangerous, even if the content originates from an internal rendering function. Always pass dynamically generated SVGs or HTML through a dedicated sanitizer like DOMPurify before injecting them into the DOM, as internal rendering logic might not properly escape all edge cases or user inputs embedded within the SVG (like project names or plot numbers). The project already had a specialized `sanitizeHtml` wrapper configured with specific SVG allowlists for this exact purpose, but it wasn't being utilized uniformly.
**Prevention:** Always use the provided `sanitizeHtml` wrapper from `@/lib/security/sanitize` when rendering untrusted or dynamically generated HTML/SVG via `dangerouslySetInnerHTML`. Make sure all user inputs used to construct SVGs are sanitized early on or just prior to rendering.
