## 2026-08-04 - Fix XSS in Client-Rendered SVG via dangerouslySetInnerHTML
**Vulnerability:** XSS via unescaped client-rendered SVG output. User inputs used to construct a mutation plan SVG via `renderFormNo3` were subsequently rendered using `dangerouslySetInnerHTML` and `document.write` on the client without being sanitized. This allowed arbitrary Javascript execution if unescaped inputs contained malicious `<script>` tags, event handlers (`on*`), or embedded `<foreignObject>` tags.
**Learning:** `dangerouslySetInnerHTML` and `document.write` are dangerous, especially when rendering SVGs constructed on the client which may contain raw user input. Generating an SVG string programmatically (e.g. string concatenation or template literals) does not automatically make it safe from XSS. The vulnerability existed because the SVG was assumed safe since it was "rendered" by an internal function, missing that the underlying payload contained untrusted inputs.
**Prevention:** All dynamically generated HTML/SVG outputs that incorporate user-provided data must pass through `sanitizeHtml` from `@/lib/security/sanitize` prior to being rendered in the DOM via `dangerouslySetInnerHTML` or passed to `document.write()`.
