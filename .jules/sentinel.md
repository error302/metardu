## 2024-05-18 - [HIGH] Fix XSS vulnerabilities in SVG rendering
**Vulnerability:** Unsanitized use of `dangerouslySetInnerHTML` for dynamically generated SVG outputs in `DeedPlanGenerator.tsx` and `MutationPlanGenerator.tsx`. An attacker could inject malicious `<script>` tags or attributes in the generated SVGs via user-supplied text (e.g. project names, survey numbers), leading to Stored XSS.
**Learning:** `DOMPurify` configuration using explicit allowlists for `ALLOWED_TAGS` and `ALLOWED_ATTRS` had the issue where all child drawing elements of SVG were stripped by DOMPurify (which was later fixed by allowing inert elements). However, manually managing the allowlist for SVGs can be brittle. `DOMPurify` has a built-in `USE_PROFILES: { html: true, svg: true }` which correctly allows standard inert SVG and HTML. To maintain security, we specifically forbid dangerous elements and attributes (`image`, `foreignObject`, `href`, `xlink:href`) instead of maintaining a giant allowlist. This correctly sanitizes HTML/SVG without breaking UI elements. We must use this configured `sanitizeHtml` wrapper from `@/lib/security/sanitize` when rendering SVGs.
**Prevention:** Always use the wrapper `sanitizeHtml` around dynamically generated HTML/SVG that is passed to `dangerouslySetInnerHTML`. Rely on `DOMPurify` profiles with blocklists (`FORBID_TAGS`, `FORBID_ATTR`) instead of manual allowlists to ensure comprehensive and secure sanitization without breaking functionality.
