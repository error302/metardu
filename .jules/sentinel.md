## 2026-10-19 - [CRITICAL] SVG DOMPurify stored XSS vulnerability via omitted sanitization and misconfigured allowed tags
**Vulnerability:** Both `DeedPlanGenerator` and `MutationPlanGenerator` components were generating internal SVG geometry strings and injecting them into the DOM directly using `dangerouslySetInnerHTML={{ __html: svgOutput }}` without invoking the `sanitizeHtml` wrapper, leading to potential stored XSS. Furthermore, the `sanitizeHtml` configuration internally broke SVG bounds rendering by explicitly defining only `ALLOWED_TAGS` and `ALLOWED_ATTRS` instead of adopting the correct `USE_PROFILES: { html: true, svg: true }` property. This misconfiguration meant critical geometry bounds were dropped, forcing earlier developers to disable sanitization to maintain functionality.
**Learning:** Security controls can be easily bypassed when their constraints break underlying functionality, leading developers to drop sanitization directly at the invocation site instead of correcting the root cause in the security utility logic.
**Prevention:** Always leverage established `USE_PROFILES` with explicit `FORBID_TAGS` in tools like DOMPurify, especially when dealing with dual HTML/SVG namespaces. Use an explicit DOMPurify attribute hook (`DOMPurify.addHook('uponSanitizeAttribute')`) to remove specific dangerous attributes like `href` or `xlink:href` rather than attempting an exhaustive whitelist of SVG element properties.
