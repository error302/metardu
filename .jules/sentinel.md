## 2025-02-27 - DOMPurify SVG Allowlist vs. Profiles
 **Vulnerability:** Empty SVG shell rendering & XSS risk via `dangerouslySetInnerHTML`.
 **Learning:** Manually maintaining an `ALLOWED_TAGS` and `ALLOWED_ATTRS` list for DOMPurify to support complex SVG drawing elements is brittle and error-prone (previously resulted in blank canvases because child drawing tags were stripped). Using `USE_PROFILES: { html: true, svg: true }` natively supports SVG safely, but requires explicitly blocking XSS vectors like `<image>`, `<foreignObject>`, and `href` attributes via `FORBID_TAGS` and `FORBID_ATTR` to prevent payload bypasses. Additionally, `sanitizeHtml` was inappropriately applied to static, trusted enums (beacon symbols), which breaks defense-in-depth principles (it was restored after review) but doesn't actually mitigate real vulnerabilities compared to dynamic SVG outputs.
 **Prevention:** Use DOMPurify's built-in profiles (`USE_PROFILES: { html: true, svg: true }`) combined with explicitly `FORBID_TAGS` and `FORBID_ATTR` for SVG sanitization. Always wrap dynamically generated SVGs (like Deed Plans and Mutation Plans) with `sanitizeHtml` before rendering via `dangerouslySetInnerHTML`.
