## 2024-03-24 - V8 Call Stack Overflow with Math.min/max on Large Arrays
**Learning:** Using `Math.min(...array)` or `Math.max(...array)` on large datasets (like point clouds or survey spot heights) can cause a V8 "Maximum call stack size exceeded" error. The spread operator expands the array into individual function arguments, and V8 engines have a strict limit on the number of arguments a function can take (usually around ~65,535). Furthermore, chaining `.map()` before `.min/max` (e.g., `Math.min(...opts.spotHeights.map(p => p.x))`) exacerbates the issue by causing redundant large array allocations, putting unnecessary pressure on memory and garbage collection.

**Action:** Whenever calculating bounds (min/max values) or operating on potentially large arrays in this codebase (particularly geographic data, point clouds, contour points, or sensor data), avoid using the spread operator with variadic functions. Instead, use a simple `for` loop or `.reduce()` to compute the values iteratively. A single `for` loop is often the most performant, executing in O(n) time with O(1) space complexity.
